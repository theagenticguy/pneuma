1. What the library actually is

strands-ai-functions takes one idea further than most agent frameworks do: a function whose body is empty, whose docstring is the task, and whose return annotation is the contract. The library builds the prompt, runs an agent, and parses a typed result. The interesting part is what it does when the result is wrong.

@ai_function
def translate_text(text: str, lang: str) -> str:
    """Translate the text below to the following language: {lang}.
    ---
    {text}
    """

print(translate_text.run_sync("It was the best of times", lang="fr"))

Four design decisions distinguish it, and each has a consequence you feel when building on it.

Post-conditions replace hoping

post_conditions are ordinary Python callables, or other AI functions, that validate the output. A failure re-prompts the model with the specific errors, up to max_attempts times, defaulting to 10 (src/ai_functions/ai_thread/config.py:115-120). The feedback is injected as a new user turn tagged [VALIDATION ERROR], so the model revises rather than restarting cold.

This is the feature that makes the library worth using. It also means a broken run reads as a silent hang and an unexplained token bill rather than a traceback — every post-condition failure is a retry, and 10 retries of an xhigh-thinking Opus call is a real amount of money.

Threads are a protocol, not a class

The load-bearing seam is Spawnable (src/ai_functions/protocols.py:299-315): two synchronous members, to_thread() and an input_shape property. Anything satisfying it gets hosted as a thread with a handle, a lifecycle, an event log, and token rollup. That is why a Claude Code session (src/ai_functions/claude_code/claude_code.py:247) and a Kiro session (src/ai_functions/kiro/kiro.py:190) are indistinguishable from a native AI function to the runtime.

The obligation weight sits on the Thread that to_thread() returns (src/ai_functions/protocols.py:128-293): seven members, four async. An implementor owes the runtime cancel checks, pause awaits, result serialization, fork semantics, and teardown.

Undeclared part of the contract

Spawnable has no name member, yet both spawn paths default the thread's display name from getattr(target, "name", None) (src/ai_functions/runtime/coordinator.py:236, src/ai_functions/runtime/worker.py:443). A spawnable without name silently loses attribution in event logs and optimizer graphs.

Teams discover each other at runtime

Every thread is handed two tools it did not ask for: list_threads to enumerate peers and send_message to delegate to one (src/ai_functions/ai_thread/tools.py:101-249). Three send modes: wait blocks on the reply, fire_and_forget discards it, continue_then_receive ends the current cycle and resumes when the reply lands.

wait carries a waits-for-graph deadlock guard that refuses an edge which would close a cycle. The check-and-register step runs with no intervening await, which is what makes it atomic on a single event loop — of two peers waiting on each other, exactly one registers and the other is refused.

Backpropagation over natural language

Named parameters — prompt fragments, learned facts, reusable Python code — live in a pluggable memory backend and are passed to functions as ordinary arguments. After a run, optimizer.step(result, feedback, backends=[...]) walks the computation graph backward and updates only the parameters responsible (src/ai_functions/optimizer/textgrad.py:307). The graph is reconstructed post-hoc from the coordinator's event log, not tracked during execution.

Passing a recalled parameter object preserves the graph edge. Interpolating it into an f-string silently drops it — the value is correct and the gradient never arrives.

2. The gap we found, and filled

The runtime lets an agent talk to peers. It does not let an agent create one. Grep confirms only list_threads and send_message are ever injected.

The hook exists and is unused. ThreadConfig.config_hook is documented as the place to inject "spawn_thread closed over the current runtime and thread_id" (src/ai_functions/ai_thread/config.py:166), called at the start of every cycle with the live ThreadContext. Nothing in the library ships that tool.

pneuma ships it. Three tools bound to the cycle context, so the agent doing the hiring is the one the runtime records as parent:

hire(role, name, mandate)   # spawn a roster class as a child thread
delegate(name, request)     # run it and read the answer back
dismiss(name)               # terminate it

Each hire passes parent_id=ctx.thread_id. That single argument writes a ThreadSpawnedEvent into the hiring agent's log, and that edge is the only thing subtree_token_usage walks — so cost attribution up an agent-built tree is a free consequence of hiring correctly rather than bookkeeping we maintain.

What the library will not do for you

No depth limit, no breadth limit, and cancellation does not propagate to children. coordinator.cancel sets one thread's signal and cancels its own task; nothing walks parent_id. A hiring cap and a finally that retires the tree are the caller's job, so pneuma enforces both.

3. An object-oriented layer over a decorator-first library

The library's surface is decorator-first: @ai_function wraps a module-level function, its docstring is the template, its signature fixes the input shape. An agent is therefore a function, and two agents differing only in private data must be two functions.

pneuma.Agent inverts it. A subclass declares the static parts in its class body and carries the varying parts as instance attributes; each instance compiles itself into one AIFunction whose prompt_fn closes over self.

class Specialist(Agent):
    role = "specialist"
    result_type = Finding
    effort = "xhigh"

    def __init__(self, plane: str) -> None:
        super().__init__(name=f"{plane}-analyst")
        self.plane = plane
        self.evidence = incident.render_plane(plane)   # private to this instance

    def brief(self, request: str) -> str:
        return f"{request}\n\nYour private {self.plane} evidence:\n{self.evidence}"

specialists = [Specialist(p) for p in ("deploys", "metrics", "logs", "traces")]

One class, four live threads, four disjoint views of the evidence. Two library details make this work.

Returning a string bypasses the template. render_prompt calls prompt_fn first; if the return is not None, that value is the prompt verbatim, and the docstring path is never consulted. So the prompt can be computed from instance state instead of interpolated from a literal.

The generated signature must be exactly one str parameter. _infer_input_shape yields STR_PROMPT only in that case, and STR_PROMPT is the only shape send_message can reach. Agent.build() therefore synthesizes that signature whatever the subclass does, and asserts the result:

fn = AIFunction(prompt_fn, self.result_type, config)
if fn.input_shape is not InputShape.STR_PROMPT:
    raise RuntimeError(f"{self.name} compiled to {fn.input_shape}, not str_prompt")
Why not decorate a method

AIFunction is not a descriptor, so self is never bound. A decorated method gets input_shape == STRUCTURED (unreachable by peers), and handing it to another agent as a tool fails with missing 1 required positional argument: 'self'. This breaks the library's own examples/compose_research_team.py:103-109. Compiling from a closure in build() avoids it.

4. The demo: an incident nobody can solve alone

A war room investigates a fabricated production incident. Four specialists each hold one telemetry plane — deploys, metrics, logs, traces — and cannot read each other's data. The incident lead holds nothing: every fact in its verdict has to be obtained from someone else, by interrogating peers or by hiring help.

The dataset is built so that convergence is mandatory rather than encouraged. Each plane alone leaves at least two mechanisms open; only the intersection of three or more narrows it to one. A module-level self_check() asserts that the four-way intersection is exactly the planted mechanism and that every pair of planes still leaves two or more candidates. "You need at least three planes" is machine-checked, not asserted in prose.

{{FINDINGS_ROWS}}
PlaneOpenMechanisms that plane alone cannot rule out

Two decoys are planted to punish single-plane confidence: an auth-svc cache-key change with a textbook collision shape that lands 11 minutes after symptom onset, and pricing-svc, which has the loudest metrics in the fleet and has not been deployed in three days.

Three layers of orchestration in one run

The war room itself is a Spawnable with no LLM in its control flow — a plain-Python thread that gets a handle, a lifecycle, and token rollup like any agent. Its execute fans out the specialists in parallel with asyncio.gather, barriers on the results, then spawns the lead. The fan-out order is ordinary asyncio, and therefore reproducible in a way a prompt-driven orchestrator is not.

LayerWho decidesMechanism
DeterministicOur PythonWarRoom.execute — parallel fan-out and barrier
Peer-to-peerThe lead, at runtimelist_threads + send_message, injected by the library
Self-staffingThe lead, at runtimehire / delegate / dismiss, injected by us

The oracle is a post-condition

The lead's verdict is graded by the library's own retry machinery. The post-condition checks the mechanism against a closed vocabulary, requires citations from at least three planes, requires that decoys were explicitly dismissed, and finally calls incident.verify. A failure names the shortfall without leaking the answer, and the model gets another attempt:

raise AssertionError(
    "the verdict does not match the evidence: " + "; ".join(problems)
    + ". Re-interrogate the specialists whose planes you leaned on least."
)

6. Configuring Opus 5 at extra-high effort

Opus 5 on Bedrock rejects the thinking configuration that earlier Claude models accept. Verified against the live API:

BedrockModel(
    model_id="global.anthropic.claude-opus-5",
    region_name="us-east-1",
    max_tokens=24_000,
    streaming=True,
    additional_request_fields={
        "thinking": {"type": "adaptive", "display": "summarized"},
        "output_config": {"effort": "xhigh"},
    },
)
SettingResult
reasoning_effort: "xhigh"Extra inputs are not permitted
thinking.type: "enabled"Rejected; the error names adaptive + output_config.effort as the replacement
thinking.budget_tokensExtra inputs are not permitted — max_tokens is the only ceiling
temperature: 0.7Rejected; adaptive thinking permits temperature 1 only
effort: "extra_high"Enum is exactly low | medium | high | xhigh | max

Effort scales thinking depth measurably. On a fixed prompt at max_tokens=16000: low produced 114 characters of reasoning in 10.5s, high 260 in 19.4s, xhigh 662 in 17.4s, max 968 in 22.6s. Thinking tokens are drawn from the same budget as the answer, so a tight max_tokens truncates the answer rather than the thinking.

Interaction with structured output

Strands strips the thinking field whenever tool_choice forces a tool, citing a Bedrock restriction. That restriction no longer holds for Opus 5 — forced tool use succeeds with adaptive thinking — so the strip is now a silent capability loss on structured-output retries. output_config survives.

7. Testing agents without calling an agent

The library ships a scripted-model harness, which is what makes 15 offline tests possible: no Bedrock, no network, 1.3 seconds. Turn objects script the model's replies and tool calls; RuntimeHarness wires a real coordinator and worker.

fn = Echo(name="boss").build().replace(
    model=ScriptedModel([
        Turn(tool_calls=(("hire", {"role": "scripted-helper", "name": "h1", ...}),)),
        Turn(tool_calls=(("delegate", {"name": "h1", "request": "when did it start"}),)),
        Turn(tool_calls=(("dismiss", {"name": "h1"}),)),
        Turn(text="done"),
    ]),
    config_hook=staffing_tools(staff, allow=["scripted-helper"]),
)

The suite asserts the properties that would otherwise only fail in production: that two instances of one class produce different prompts, that every compiled agent lands on STR_PROMPT, that specialists' evidence is genuinely disjoint, that hire writes a parent edge into the hiring agent's log, that the hiring cap holds, and that a bad tool call comes back as recoverable text rather than an exception.

Writing them forced a real design change. Testing delegate meant a hired subagent had to run on a scripted model, which meant Agent needed a model() method rather than hard-coding opus5() inside build(). The test suite found the missing seam.

8. Defects found in the library

A sixteen-agent documentation pass over the codebase, one agent per perspective, surfaced these. Each is cited in the document that found it.

DefectWhy it matters
generate_signature_from_model is defined twice; the copy with zero callers sorts required parameters before optional, the reachable copy does not Any local-code-execution user whose output model declares an optional field before a required one crashes. The two-line fix is already written, in a file nothing imports.
The Claude Code mirror of send_message has no deadlock guard The Strands path refuses a mutual blocking wait; two Claude sessions waiting on each other hang with no refusal.
ThreadStatus.TERMINATED and FAILED are declared but never assigned Termination deregisters the thread instead, so a caller polling handle.is_done() gets ThreadNotFoundError rather than True.
Malformed wire frames are dropped by except Exception: continue with no log line at any level The library's one completely silent failure path, four lines below a transport-close bug that was fixed for exactly this reason.
@ai_function on a method leaves self unbound Breaks examples/compose_research_team.py when that method is handed to another agent as a tool.
A --url flag is documented in three docstrings and does not exist; the parameter is accepted and immediately deleted Documented CLI behavior that silently does nothing.
config.py instructs users to install a [procedural] extra that is not declared smolagents is already a hard dependency; the instruction is stale.
Returning a t-string from a prompt body, which the tutorial calls "the preferred way", raises TypeError The documented happy path for Python 3.14 templates does not run.
Remote resolve_approval returns True unconditionally after scheduling under suppress(Exception) Its docstring promises "True iff a matching pending future was resolved".
ThreadContext.metadata is passed by reference from worker state A thread mutating it mutates worker state for every later cycle.
claude_code/ and kiro/ — 1,930 LOC across the two external-process boundaries — have zero test references The two riskiest integration surfaces are the two untested ones.
hatch run check-spec is a required gate in CONTRIBUTING.md and absent from CI A hand-maintained 10,618-LOC stub tree has no machine gate.

Also worth knowing when building: PyPI 0.3.0 predates runtime/usage.py, so the subtree token-rollup helpers exist only on the git HEAD. pneuma pins the clone.

9. Assessment

The abstraction earns its keep. Post-conditions turn "the model usually gets this right" into a loop that either satisfies a check or fails loudly, and that alone justifies the dependency for any workflow where a wrong answer propagates. The Spawnable protocol is the better idea: making a Claude Code session and a decorated Python function interchangeable to the runtime is a genuine architectural result, and the cost of implementing it is two methods.

The rough edges are alpha-stage rough. Cancellation not propagating to children, no depth or breadth limits on spawning, two declared statuses that are never assigned, and a silent frame-drop path are the kind of thing you discover by reading the source rather than the README — which is what the documentation pass was for. The 22k LOC are unusually well commented, with a repo-root INVARIANTS.md naming twelve runtime invariants and their enforcement sites, and that made the defects findable.

Building an object-oriented layer on top was easier than expected, for one reason: prompt_fn returning a string bypasses the template machinery entirely. That single escape hatch is what lets an agent's prompt be a method on an object rather than a docstring on a module-level function, and everything pneuma does follows from it.

The self-staffing tools are the part we would upstream. The hook is already documented, the parent-edge plumbing already produces correct cost rollup, and roughly 90 lines closes the gap between an agent that can talk to its peers and an agent that can build a team.
